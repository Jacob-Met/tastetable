# TasteTable — current result

[Download and run v0.3.9 focused week](https://github.com/Jacob-Met/tastetable/releases/tag/v0.3.9-focused-week) · [Phone screen](https://github.com/Jacob-Met/tastetable/releases/download/v0.3.9-focused-week/working-week-phone.png) · [Desktop screen](https://github.com/Jacob-Met/tastetable/releases/download/v0.3.9-focused-week/working-week-desktop.png)

A caregiver can read the seven-day plan, save it privately, add a reply on a dated visit, return to that visit and reopen the complete saved week. Infrequent file and calendar controls are folded away. The runnable package uses fictional fixture venues.

## Highest visible gaps

1. **Unfamiliar live requests have no proven useful answer.** The published runner uses fictional fixtures, so its venue choices and constraint outcomes do not establish real current provider behavior or care suitability. Try actual varied provider responses before claiming a dependable real-world plan.
2. **Care checks can be mistaken for venue facts.** Low-sodium, texture and step-free access still come from heuristic tags/keywords, not a confirmed current menu or entrance. The screen must make the unconfirmed part unmistakable at the decision point.
3. **A caregiver must move between the week and prior-visit records to compare outcomes.** The current dated reply stays visible, but recent visit outcome context can still be far from the next choice on a narrow phone.
