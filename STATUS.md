# TasteTable — current result

[Download and run v0.3.11 visit outcomes](https://github.com/Jacob-Met/tastetable/releases/tag/v0.3.11-visit-outcomes) · [Phone screen](https://github.com/Jacob-Met/tastetable/releases/download/v0.3.11-visit-outcomes/working-week-phone.png) · [Desktop screen](https://github.com/Jacob-Met/tastetable/releases/download/v0.3.11-visit-outcomes/working-week-desktop.png)

A caregiver can read the seven-day plan, save it privately, add a reply on a dated visit, return to that visit and reopen the complete saved week. Original care checks appear beside each suggested visit as questions to confirm with the venue. Imported prior visit records mark both completed and missed trips beside the next matching choice. Infrequent file and calendar controls are folded away. The runnable package uses fictional fixture venues.

## Highest visible gaps

1. **Unfamiliar live requests have no proven useful answer.** The published runner uses fictional fixtures, so its venue choices and constraint outcomes do not establish real current provider behavior or care suitability. Try actual varied provider responses before claiming a dependable real-world plan.
2. **Previous outcomes are invisible until their records are imported again in each tab.** The main week does not provide an immediate route to open the private visit-history picker, so repeat visits can look new even when useful records exist. Keep the deliberate privacy boundary, but put that action beside the decision.
