# V2 pre-execution receiving corrections

V1 was frozen before candidate body or metadata exposure. That immutable controller and its complete freeze remain retained. The candidate metadata was subsequently released, and Forge and Loom reviewed V1 with product source available to them. Root has not opened candidate implementation bodies, but this correction is informed by their source-aware observations. V2 must not be labelled wholly candidate-blind. Neither V1 nor V2 has executed against the candidate at this freeze.

The source candidate, all fixtures and expected facts are unchanged. The exact executable diff is controller-diff-v2.patch. There are five narrow corrections:

1. Pending reads must retain the accepted filename and original received/saved timestamps with visible prior metadata. A pending annotation is allowed, so the observer no longer requires the complete source container text to equal its previous text.
2. Invalid-JSON, UTF-8 and both size refusals wait for the settled side-specific reason and absence of a reading status. A generic side prefix alone was insufficient to establish completion.
3. Remote-network observations distinguish HTTP, HTTPS, WS and WSS from inline data resources. All requests remain in the receipt; actual network requests must stay at the owned loopback origin.
4. The file-action request boundary is after intentional model/module imports and before the first actual file selection, including initial rendering and screenshots.
5. Scope is explicit: the native course exercises keyboard focus but does not navigate the planner link. The separate-tab planner entry is a static source-review finding. Storage instrumentation observes Storage.setItem only; broader source behavior is separately reviewed. Departure is a dispatched pagehide event, not real navigation. These qualifications supersede the broader claims in criteria-v1 items6–7.

The output moves to received-v2 and uses a V2 receipt schema. This is the first actual candidate receiving course. There are no added test cases or repeated product qualifications. Browser/server closure and source/input preservation remain required. An outer direct-process collector will impose a finite deadline and preserve complete streams; a timeout cannot be accepted as a closed successful course.
