## Frozen comparison boundary

1. Paired occurrences require semantic equality of the **complete parsed response and inputs**, together with equality of receivedAt and calendarId. Object member ordering and JSON whitespace do not change meaning; array order does. A different savedAt is normal for a later arrangement. The file's identity and provenance are declarations, not authentication or a new provider check.
2. Every original occurrence remains distinct by its original pick index. Equal venue IDs or names do not collapse repeated visits. The existing model defines meals in source order followed by the optional outing.
3. Dates are full Gregorian dates. Moving a Monday-anchored week changes scheduled dates even when every weekday selection stays the same. Two visits on one day remain two visits. Omitted visits have no scheduled date.
4. A source or declared identity mismatch produces separately dated arrangements with an honest explanation that occurrences have not been matched. It must not assert paired moves across those files.
5. The consumer retains meaningful context from each file: filename, received/saved times, source label, original inputs and constraints, week range, original suggestion day, current date or omission, identity/name and original explanation. Any displayed affinity remains the saved numeric value with its existing meaning; counts or affinities must not become invented scores, percentages or new checks. Notes remain original file content.
6. Empty native plans and all-omitted arrangements must be understandable, with no invented visit, lost occurrence or false successful match count.
7. File names and file-contained strings render as literal text. The authentic literal-city input and explicitly labeled structural variants exercise this boundary without introducing real private data.
8. Invalid JSON, invalid UTF-8, incompatible saved-week structure and the consumer's declared file-size bound must refuse use and retire stale results for the affected selection. A later valid choice must recover. If the source has asynchronous reads, a deliberately delayed **real File read** will test that an older selection cannot replace a later selection or revive cleared results; the delay changes timing only.
9. Reading or comparing must not rewrite original file bytes, call a provider, write storage, or change an already open planner's current arrangement and accepted data. Witnesses include exact input hashes, storage-write observations, network requests and the planner's actual saved result before/after comparison.
10. The static comparison page must remain usable with already loaded assets and network disabled while the user chooses local files. This gate follows the actual separately served static page; a new offline bundle or resumable-file format is outside the proposed consumer.

These are behavioral expectations, not required DOM selectors or exact prose. A driver adapter may locate the actual controls after this freeze; it may not derive expected results from the new comparison model.
